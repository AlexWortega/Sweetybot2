The following pilot results describe the completed historical v02 24-hour cycle, not v05. B or RB/R1 toggles walk/run; LB/L1 remains the deadman. A hysteretic runtime switches to recovery after a persistent fall, then returns to the selected motion mode after sustained upright stability.

The first 120-second locomotion pilot completed 1,032,192 transitions and 126 optimizer updates. A preliminary development test of 24 eight-second episodes had no falls. The forward command of 0.20 m/s produced mean local forward velocity 0.196 m/s. Overall linear RMSE was 0.181 m/s and yaw RMSE 0.619 rad/s; backward, side and turn commands remain poor. This pilot fails the full quality gate. Its video is a preliminary result, not proof of running or rough-terrain performance.

Training retains the v02 masses, joint layout and dimensions. It uses 12 learned leg targets and four neutral head/ear targets, stable per-joint PD, voltage-dependent directional drive/braking limits, delays and a backlash approximation. It applies no virtual support wrench, bias-force compensation, root support force or active-episode pose corrections. Initial episode poses are lifted clear of terrain. Training disturbances are explicitly sampled velocity impulses, with no vertical support.

The actor receives IMU-like signals, encoders, commands, previous actions and three-frame history; it receives no root position or root linear velocity. Native MuJoCo advances at 500 Hz, policies at 50 Hz. Recovery retains torso, head and ear contacts and adds conservative contact to the existing horn capsule. The motor model is not identified from physical STS measurements.

The curriculum includes flat ground, rough heightfields, slopes and steps. Walking requests up to0.60m/s and running up to0.65m/s; the runtime run limit defaults to0.60m/s. Actual fast performance must be measured. Final tests cover up to8degrees slope and25mm terrain height range. Terrain spans20m so valid fast motion is not penalized by a small arena. These ranges do not establish universal terrain capability. Running evaluation requires surviving, finishing stable, mean forward speed>=0.35m/s and>=70% requested speed, at least two clean flight intervals>=40ms and>=3% valid forward flight samples. Ground-supported body motion, shuffling and jumping in place do not satisfy the criterion.

Development evaluates every command and all four recovery conditions separately. Legacy `prone` is a folded upright crouch, not an inverted pose; both sides and supine are separate tests. Final seeds 3000000..3000099 are reserved before the main run. The original preview used seed 2000000, which was removed from the final set before curriculum training.

The quality gate requires measured motion, command survival, yaw tracking and RMS joint torque at or below the engineering rated-torque screen 1.5691 Nm. Recovery requires at least 50% success for each orientation in every development terrain. Thermal durability and physical recovery are unverified. Simulation target slew is 5.5 rad/s; it does not replace the conservative hardware bring-up command contract.

Training uses CPU MuJoCo simulation and a small Torch GPU learner with a 2 GiB allocator limit, plus CUDA context. The driver checks available GPU memory and can fall back to CPU. Each source snapshot is immutable while a worker is active; checkpointed handoffs preserve the original deadline.

The README preview uses development seed 1000090 on flat ground, 8 simulated seconds at real-time playback speed, no mid-episode resets, and the saved v02 CAD visuals. Its manifest records exact checkpoint hashes. The preview is separate from aggregate development scoring. At capture, best walking survived 189/192 development trials, running survived 54/96 with 0/96 strict running successes, and recovery completed 0/128 fallen starts. Maximum development RMS torque was 2.10 Nm for walking and 1.86 Nm for running, exceeding the 1.5691 Nm screen. No skill passed its complete gate. These scores use mild development terrain (difficulty 0.2), not the full final terrain range.

See [learning instructions](../learning/README.md) for setup, evaluation and joystick mapping. A physical joystick was not connected during setup; SDL reported zero devices. CPU replay, checkpoint loading, rendering and supervisor logic were exercised.
